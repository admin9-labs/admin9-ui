# AFileUploader 组件决策

- 状态：已实施
- 决策日期：2026-08-20
- 首次发布：`0.7.0`

本文记录 `AFileUploader` 成为独立公开组件时的关键取舍，不是当前 API 定义。现行契约以 [AFileUploader](../components/file-uploader.md)、[AFilePicker](../components/file-picker.md) 和源码为准。

## 背景

`AFilePicker` 原本同时负责文件浏览、选择和上传队列，职责偏重，也无法让其他应用页面复用上传交互。需要将上传事务抽成独立能力，同时保持 Picker 的选择确认语义。

## 决策

- 将 `AFileUploader` 作为公开组件，供 `AFilePicker` 和应用页面复用。
- 组件负责本地文件队列、进度、取消、重试、部分成功、结果校验和异步生命周期。
- 继续复用单文件 `FileUploadCapability.upload`，由组件逐项调度，不增加 batch service。
- 每个队列绑定一个具体 `FileType` 和该类型下的 `groupId/null`；本地多选不表示混合业务类型。
- `accept` 只作为原生文件选择提示，不用于推断业务类型或代替安全校验。
- 上传结果只有在 ID、类型、状态和 URL 合法且不重复时才计入成功项；单项失败不回滚其他成功项。

## 与 AFilePicker 的组合

- Picker 复用 Uploader 的队列和事务状态，不再自行实现进度、取消和重试。
- 聚合视图中的上传目标使用最近选择的具体类型或允许类型中的第一项，目标分组为 `null`。
- 上传完成后刷新当前列表，但不自动加入选择草稿，也不写回 `v-model`。
- 上传进行中仍可继续选择文件，新任务追加到当前具体类型和分组的队列。
- 关闭 Picker 时取消活动上传并屏蔽迟到回调，上传交互不创建嵌套 Modal。

## 未纳入范围

- 网络文件、扫码上传和其他上传来源；
- 后端批量上传接口；
- 文件删除、移动和分组管理；
- 具体 API、认证、权限和业务字段。

这些能力只有在获得真实应用与 API 契约，并证明能够跨项目复用后，才考虑进入公共组件；否则由应用实现。

## 结果

上传事务与业务选择相互独立：Uploader 报告上传结果，Picker 仍由用户显式选择并确认。应用后端继续负责文件内容、类型、大小、身份、资源归属和目标分组权限校验。
